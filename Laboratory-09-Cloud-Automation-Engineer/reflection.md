# Mission Reflection: Cloud Automation & DevOps Engineering

Automation is critical when managing hundreds of cloud servers because manual administration scales linearly with infrastructure size, making routine tasks slow, unsustainable, and highly vulnerable to human error. Without automation, maintaining a large-scale distributed fleet would require an impossible amount of manual labor hours.

However, automation introduces significant potential dangers. If a destructive typo—such as an unintended deletion command—exists inside a script scheduled to run across 1,000 servers, the mistake propagates instantaneously, resulting in catastrophic, widespread data loss in mere seconds.

Writing a Bash script differs substantially from creating a Docker Compose YAML file. A Bash script executes procedural, sequential shell commands and logical control flows interpreted directly by the operating system shell. Conversely, Docker Compose uses a declarative configuration approach to define multi-container application stacks, networks, and persistent volumes simultaneously.

Reviewing my entire GitHub repository from Laboratory 1 to Laboratory 9, my understanding of cloud computing has transformed profoundly. I have transitioned from learning foundational cloud concepts to mastering infrastructure provisioning, multi-cloud platforms, containerization, operational pipelines, and infrastructure automation.

Among all the roles explored throughout the semester, I enjoyed the Cloud-Native Engineer role the most. Building scalable application architectures using containers and modern orchestration tools provided the most engaging, hands-on insight into how resilient, production-ready cloud applications are designed and deployed.
